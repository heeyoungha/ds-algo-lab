## 🔹 프록시 서버란?

프록시 서버(Proxy Server)는 클라이언트와 서버 사이에서 중개 역할을 하는 서버입니다.

```
[클라이언트] → [프록시 서버] → [목적지 서버]
```

### 간단한 비유
- 우체부(프록시 서버)가 편지를 받아서 실제 주소(목적지 서버)로 전달
- 클라이언트는 프록시 서버의 주소만 알면 되고, 실제 서버의 주소는 몰라도 됨

---

## 🔹 프록시 서버의 주요 역할

### 1. 요청 전달 (Forwarding)
- 클라이언트의 요청을 목적지 서버로 전달
- 목적지 서버의 응답을 클라이언트로 전달

### 2. 로드 밸런싱 (Load Balancing)
- 여러 목적지 서버에 요청을 분산
- 서버 부하를 균등하게 분배

### 3. 캐싱 (Caching)
- 자주 요청되는 데이터를 저장
- 응답 속도 향상

### 4. 보안 (Security)
- 클라이언트의 실제 IP를 숨김
- 방화벽 역할 수행

### 5. SSL 종료 (SSL Termination)
- HTTPS 요청을 받아서 HTTP로 변환하여 내부 서버로 전달
- 인증서 관리 단순화

---

## 🔹 프록시 서버의 장점

### 클라이언트 관점
- ✅ 단일 접근 지점 제공
- ✅ 복잡한 내부 구조를 숨김
- ✅ 빠른 응답 (캐싱 활용)

### 서버 관점
- ✅ 트래픽 제어 가능
- ✅ 보안 강화
- ✅ 서버 부하 분산

---

## 🔹 프록시 서버 동작 방식

### 일반적인 요청 흐름

```
1. 클라이언트가 프록시 서버에 요청
   GET http://proxy-server.com/api/data

2. 프록시 서버가 요청을 받음
   - 요청 분석
   - 목적지 서버 결정

3. 프록시 서버가 목적지 서버에 요청 전달
   GET http://backend-server:8080/api/data

4. 목적지 서버가 응답 반환
   HTTP 200 OK { "data": "..." }

5. 프록시 서버가 클라이언트에 응답 전달
   HTTP 200 OK { "data": "..." }
```

---

## 🔹 nginx를 사용한 프록시 설정 예시

### 기본 프록시 설정

```nginx
server {
    listen 80;
    server_name myapp.local;

    location / {
        proxy_pass http://backend-server:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

### 설정 설명
- `listen 80`: 프록시 서버가 80 포트에서 요청을 받음
- `server_name myapp.local`: 도메인 이름
- `proxy_pass`: 요청을 전달할 목적지 서버 주소
- `proxy_set_header`: 요청 헤더 설정
